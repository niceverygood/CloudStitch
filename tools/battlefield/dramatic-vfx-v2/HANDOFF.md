# Cloudstitch · 질량과 명암을 다시 설계한 함포

`dramatic-vfx-v1`의 기술 검사와 표현 평가는 구분한다. 이전 CPU42·실전16건은 당시 소스의 기술 근거다. 실제 .19초 A/B에서는 작은 반투명 꽃잎만 보이고 큰 충격 덩어리·명암·연기가 부족했다. 이전 원본·0.1.0 history·0.1.1·PNG·PASS·preview404 기록을 그대로 보존하고 새 폴더에 수정한다. 새 표현을 이전 PASS로 승인하지 않는다.

이번 핵심은 채워진 유기적 돔·연기 덩어리, 크림 중심과 황동 테두리·짙은 세이지 밑 명암, 비대칭으로 길게 휘는 압력 획, 실제 목재/산호색 파편이다. 큰 형태는 텍스처의 투명한 여백에 의존하지 않는다. 아틀라스는 보조 잔광·연무에 사용한다. 둥근 곡면과 직접 만든 불규칙 가장자리로 손그림 같은 입체감을 유지한다.

## 실제 크기와 비교 조건

현재 통합 소비자의 플레이어 모델은 `shipAsset('player-homeward',10)`으로 정규화된다. 이전 인계의18은 다른 뷰어의 전제였으므로 이 소비자에는 적용하지 않는다. 길이10은 표시 단위이며 미터·충돌·피해 수치가 아니다.

주 충격 덩어리는 길이10 선체에 대해 표시폭6~8을 목표로 한다. 두 비대칭 압력 날개와 파편의 바깥 실루엣은12~14, 후속 연기는8~10을 목표로 구분한다. 명암이 있는 큰 덩어리를 먼저 읽고 중간 파편·작은 잔광을 읽게 한다. 실제 픽셀 투영·가림·체감은 브라우저 결과로 별도 확인한다.

CPU의 대표 직교 투영 측정은 .19초 주질량6.7439·날개 포함12.8785, .80초 연기9.9595다. 큰 주형태는 텍스처 없이 vertex color로 채운48분할·5겹의 둥근 돔5개와 비대칭 압력 날개2개다. 주형태 불투명도 .96~.98, 실제 채워진 삼각 면적도 검사했다. 전체 stage는57mesh·114geometry/material이며 각각 정리한다. 새 stage/runtime14건이 통과했고, 그대로 재사용한 feedback20·작살9건은 이전 결과를 유지한다. 이 수치는 새 실제 전투·픽셀·미술 승인을 대신하지 않는다.

비교판 선체 길이는5.2이므로 함포 두 항목의 양쪽 geometry 변환을 `5.2/10=.52`로 맞췄다. 기존 원본도 같은 변환을 사용한다. 월드 접점·법선·방향·클립 속도·사건 시각은 공통이다. 표적 중심을 가리던 불투명 판은 함포 명중에서만 양쪽 동일한 빈 테두리로 바꿨다. 배치용 포구·표적 간격은 원래 값을 유지한다.

다른45종의 이전 풍성 프로파일과 작살 시연의 .32 변환은 보존한다. 이들이 실제 게임에서 같은 단위로 구현됐다는 뜻은 아니다. 대표3종 중 함포2종을 이번에 재설계하고, 작살의 읽기 쉬운 단일 발사체·반동·줄 채찍은 이전 작업을 재사용한다. 작살 걸림·견인 판정은 없다.

## 소비 API와 권위

```js
import { createDramaticCannonVfx } from './cannon-runtime.mjs';
// projectileVfx: 이전 실제 투사체 소비자. 새 비행 경로를 만들지 않는다.
const cannon = createDramaticCannonVfx(THREE, scene, {
  projectileVfx, camera, reducedMotion, atlas,
});
```

기존 API와 단일 sim 시계를 유지한다. 함포 포구 .95초·명중1.60초 동안 표시를 평가한다. 실제 fire/hit 한 사건당 한 stage이며 actual XYZ/+Z 발사 방향/+Y 접촉 법선을 사용한다. 피해·HP·사거리·충돌·실제 투사체 좌표를 바꾸지 않는다. 활성·풀 상한과 caller atlas의 소유권·정리를 유지한다. 새 재질은 OutlineEffect의 사각 외곽선에서 제외하고 명암과 가장자리를 직접 그린다.

기관총은 승인된 기존 soft runtime 한 경로다. feedback은 동결된 `dramatic-vfx-v1/feedback.mjs`를 그대로 재사용한다. 안정된 base camera로 조준하고 이전 표시 반동을 복구한 뒤 실제 포구를 구한다. 카메라 반응은 최종 draw에 한 번 적용하고, soft와 cannon의 기존 활성 carrier ID만 대상으로 `update(0,...,finalCamera)`를 호출해 같은 나이에서 정렬한다. 두 번째 sim/feedback 업데이트나 새 consume은 없다.

`drainCues()`는 오디오 재생이 없는 관측 계약이다. 새 후보 음원을 자동 설치하거나 기존 이벤트 오디오와 중복 재생하지 않는다. 사람의 미술·손맛·청감 승인은 별도다.

## 빌드와 검수

```sh
node tools/battlefield/dramatic-preview-v2/build.cjs
```

출력은 `outputs/combat-dramatic-v2/preview.html`이다. 먼저 같은 카메라·시간의 함포 명중 .19초와 후속 연기 .45~.60초를 비교한다. 큰 질량·명암이 실제 보이는지 확인한 다음 실제 함포 명중 좌표·HP·피격면·종료/회수를 좁게 검사한다. 변하지 않은 기관총·기존26건·feedback20건을 새 증거 없이 반복할 필요는 없다.

소스 담당의 경량 검사 수와 정확한 파일 해시는 manifest에 기록한다. 빌드·브라우저·이미지·실전·미술 결과는 각각 실행한 새 보고서에 결속한다. 최신 10배 이상의 대담함은 설계 목표이며 수치 곱이나 기술 PASS만으로 달성했다고 표시하지 않는다.
