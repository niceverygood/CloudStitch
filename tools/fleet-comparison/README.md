# Cloudstitch 함대 비교판

`outputs/fleet-comparison-v1/index.html`의 주 목록 71개는 새 함대 제작 항목 62개와 초기 디자인 대안의 **v1 리깅 해석 파생본 9개**다. 장비 구성·상태·역할·시설·기록을 포함하므로 고유 정사 함선 71종을 뜻하지 않는다. 기존 v1/v2 모델·뷰어·전투와 진행 상태는 보존한다.

초기 고밀도 생성 원본 A1~C3는 `outputs/airship-models-9/model-manifest.json`의 별도 9개 파일이다. 주 목록의 `design-a1`~`design-c3` 리깅 해석본과 파일·형상·용량이 다르다. 과거 안내의 “초기 원본 9개 보존 캡처”라는 표현은 이 차이를 빠뜨렸으므로 여기서 바로잡는다. 비교판의 `archiveOriginals` 구역은 고밀도 원본 9개와 당시 렌더 이미지를 따로 연결한다. 동일 디자인의 원본 참고이며 새 함종 9개를 더한 것이 아니다.

비교 화면은 이미지 두 장으로 시작하고 선택한 한 척만 3D 대화상자에서 연다. 다른 배를 열거나 닫으면 앞선 iframe을 제거하도록 구성한다. 민간선·라이벌의 관계는 등장 맥락으로 설명하며 자동으로 적으로 분류하지 않는다. 6판의 중간/최종보스 12배정은 훈련용 교전 편성이고, 정사 캠페인 지역 보스·미확정 슬롯은 별도 표기한다.

## 생성과 확인

```sh
node tools/fleet-comparison/capture.cjs --resume
node tools/fleet-comparison/build.cjs
node tools/fleet-comparison/verify.mjs
```

캡처는 기존 뷰어에서 새 비교판 PNG만 생성한다. 현재 모델 SHA와 일치하는 v2 미리보기 13개 및 초기 대안의 v1 리깅 해석본 캡처 9개를 복사하고 나머지 49개는 실제 v2 모델에서 만든다. 정확한 최종 수량·방식은 `previews.json`을 따른다. 별도 원본 참고 9개는 고밀도 원본의 당시 렌더 PNG를 `originals/`에 복사하고 기존 고밀도 GLB와 원본 갤러리를 연결한다. 이 과정은 원본 재생성·GLB 복제·신규 모델 렌더가 아니다. 빌드·캡처에는 기존 설치 의존성과 통합 담당의 브라우저 실행 순서를 따른다.

구조 검사는 추가 의존성이 없으며 `inventory.json`, `previews.json`, 원본 소스/출력 카탈로그와 초기 고밀도 원본 manifest를 읽는다. 주 목록 PNG 71개와 별도 원본 참고 PNG 9개, 합계 80개의 헤더·청크 범위·SHA256을 확인한다. 주 목록의 모델 SHA는 v1/v2 카탈로그에, 원본 참고의 모델 SHA는 초기 모델 manifest에 대조한다. 각각의 실제 GLB 경로·바이트 길이, 6판 12개 보스 참조, 근거 파일·미정 상태와 원본/리깅 해석본 구분도 확인한다. HTML에 들어간 데이터가 목록과 같은지, 두 이미지와 한 iframe 정책이 정적으로 연결되는지도 확인한다.

결과는 `outputs/fleet-comparison-v1/verification-structure.json`에 쓴다. 실제 데이터 준비 전에는 `--help`와 구문 검사만 실행한다. 원본 고밀도 모델과 기존 v1/v2 모델을 다시 해시하지 않으며 `outputs/fleet-v2/source-manifest.json` 한 파일만 동결 SHA `916c3e9790818490ee6d4457b7e41d8fe23cc49130996f64512a3c2a2657f68e`와 비교한다. 모델 SHA는 각 출처의 기록과 대조하고 파일 존재·크기를 확인한다.

## 검증 한계

PNG 검사는 픽셀 디코딩·미술 품질 판정이 아니다. 정적 iframe 검사는 실제 GPU 자원 해제·브라우저 상호작용·모바일 가로 넘침 검증이 아니다. 3D 원본의 재질·7클립·부품 연결 구조 전체를 이번 검사로 다시 승인하지 않는다. 미리보기는 화면에 맞춘 크기이므로 실제 크기 비교와 다르며, v2 뷰어의 귀환호 상대 비교도 임시 제작 단위다. 새 소켓·충돌·전투 기믹·정사 보스 단계 구현과 사람의 실루엣/손그림 선호 검토는 별도다.
