# Cloudstitch 함대 v2 캐릭터 기준

2026-10-18 사용자 요청: 주인공·일반 적·보스가 같은 선체와 선장실에 장비만 바꾼 모습이므로, 외곽 형태와 세력의 재료를 먼저 바꾼다. 이 폴더의 작업은 기존 함대의 **외형 개선판**이다. 새 정사 함종·새 무기·새 전투 시스템을 추가하지 않는다.

`profiles.mjs`의 버전은 `fleet-identity-2.0.0`이다. 원본 `tools/fleet/`, `outputs/fleet-v1/`, 선택 귀환호 GLB, 초기 고밀도 디자인9개는 보존한다. 프로필62개는 선택 귀환호 보존1개와 새 외형 대상61개다. 역할·시설·기록·세력스타일·결말 상태가 섞였으므로 **고유 함선62종이 아니다.** 초기 `design-*`9개는 개선 대상으로 세지 않는다.

## 기준과 해석

- 사용자 확정 아트: 크림색 천·꿀빛 목재·청록색 지붕/기계·황동·산호색 수선. 사실적 금속 광택보다 손으로 칠한 큰 색면과 단순한 명암을 사용한다.
- 정찰/봉쇄/인양/수리/돌진/위장은 `outputs/09-enemies.txt`, `25-enemy-ai-encounters.txt`를 따른다.
- 네 세력 재료와 노출 골조 규칙은 `outputs/65-enemy-modular-anatomy.txt`를 따른다. 장식 케이블이 실제 약점과 같은 굵기로 보이지 않게 한다.
- 첫 보스는 `outputs/10-first-boss.txt`의 거대한 장례 전함·중앙 종실, 조선소는 `14-living-shipyard-boss.txt`의3개 수평 도크·크레인·환기구, 왕은 `31-act3-main-quests.txt`의 파손 함대와 기억 모듈 시험, 최종 시설은 `43-final-boss-encounter.txt`의 기계 봉인 심장1·탑3을 기준으로 한다.
- 정사에 선체가 없는 역할형·임무선의 상세 외형은 이번 제작 제안이다. 왕관형 돛대·초승달 선체·수리 쌍동선 등의 형태를 원문에서 이미 확정한 것으로 쓰지 않는다.
- 같은 플레이어 빌드는 귀환호의 작은 뒤 선장실·원형창·산호 삼각 패치를 이어받는다. 주인공의 성장형까지 전혀 다른 사람의 배로 바꾸지 않는다. 대신 갑판의 폭, 아웃리거, 기낭 배열, 빈 작업 공간을 바꾼다.

## 프로필 계약

`PROFILES`, `PALETTES`, `FAMILIES`, `SHOWCASE_IDS`, `LANDMARK_CODES`, `getProfile(id)`, `resolveArtModules(ship, fallback)`를 내보낸다. 각 항목은 다음을 명시한다.

- `family`: 새 body geometry 계열. 색만 교체하는 분류가 아니다.
- `length/width/depth`: X방향 길이·Z방향 폭·Y방향 선체 깊이. 선수는 -X, 위는 +Y. 모든 수치는 로컬 아트 LU이며 미터·전투 충돌·장착 소켓 규격으로 쓰지 않는다.
- `envelope`: `layout/length/radius/flatten/height/offset/ragged` 및 일부 `asymmetric`. `single-high`, `side-twin`, `triad-low`, `low-inline`, `none`으로 한개의 높은 크림 기낭 반복을 피한다.
- `cabin`: `shape/position/scale`. `scale`은 [길이, 높이, 폭]. 주인공 cottage 외에도 armored-slab, gantry-booth, workshop, lantern-pod, open-helm, seal-vault, control-bridge, open-belfry, dock-control, crown-throne, observation-dome, cargo/mail/market/shelter 부스, unfinished-frame, none을 구별한다. `none`은 집을 렌더하지 않는다.
- `landmarks`: 제작할 역할·세력별 실루엣 요소. 코드가 선언되었다는 사실은 실제 geometry 완성의 증거가 아니다. 빌드/브라우저에서 구현된 형상을 별도로 검사한다.
- `palette`: 질감은 재사용해도 색면·밧줄·판금·빛을 세력별로 분리한다. `ghost` 잔광을 선체 전체 투명화로 구현하지 않는다.
- `artModules`: 뷰어용 배치 제안이다. `resolveArtModules`는 fallback → 제안 → 카탈로그 정수 순으로 합쳐 기존 정수 명세를 보존한다. `null`은 미정이며 제안 수를 정사 수로 승격하지 않는다.
- `structuralFeatures`: 소스가 명시한 시설 수/구조는 보존한다. 최종3탑 등은 기낭/무장 수와 다른 구조물이다.
- `preserveOriginal`: 귀환호 원본을 그대로 쓴다. 기획의 전투 damage·상태 소유권에 영향을 주지 않는다.

## 외형 검수와 한계

세력 색을 지운 실루엣에서도 일반 적6역할·첫 보스·왕·시설을 구별해야 한다. 동일 카메라에서 서로 다른 family가 같은 코티지·단일 고기낭·동일 배 외곽으로 보이면 개선 실패다. 보스 크기는 귀환호와 같은 LU로 나란히 놓아 확인하고, 개별 뷰어의 화면 맞춤을 실제 크기 차이의 증거로 쓰지 않는다.

종실/수리 도크/조선소 가운데 빈 공간, 노출된 연결 골조, 후방 추진부, 갈라진 돛의 실제 형상을 확인한다. 이 문서와 데이터 검사만으로 그 브라우저 검수를 통과했다고 쓰지 않는다. 기존 원화의 손그림 완성도에 도달했다는 주장도 하지 않는다. 프로시저 geometry·질감 개선은 외형 제작 시제품이며 최종 캐릭터 원화·부품별 엔진용 소켓·충돌·LOD는 별도다.

개별 데이터 검사 명령: `node --check tools/fleet-v2/profiles.mjs`. 카탈로그 대조에서는62 ID 완전대응,design-*제외,팔레트/family/치수의 유효성,모듈 정수 보존을 확인한다. 전체 빌드·브라우저·원본 해시 검사는 통합 담당이 기록한다. npm/의존성 변경은 필요 없다.
