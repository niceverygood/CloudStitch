# Cloudstitch 6개 판 교전 시제품

기존 함대 GLB를 불러와 이동·사격·공격 예고·피격과 각 판의 중간보스/최종보스를 시험하는 별도 브라우저 전투 시제품이다. 사용자 요청에 따라 지역6개를 플레이판6개로 구성했다. 최종 게임 엔진·플랫폼 선택이나 전체 캠페인 완성을 뜻하지 않는다. 원본 기획·함대·선택선 리깅을 보존한다.

## 실행

저장소 루트에서 실행한다. Node.js20 이상, npm, 실제 Git LFS 자산이 필요하다.

```sh
npm ci
npm run setup:browser
npm run build:encounters
npm run verify:encounters
python3 -m http.server 8840 --bind 127.0.0.1
```

브라우저에서 `http://127.0.0.1:8840/outputs/encounters-v1/`을 연다. 기존 뷰어처럼 HTML 하나를 직접 여는 방식과 다르다. 저장소 루트를 서버로 열어야 `../fleet-v1/ships/<assetId>.glb`를 상대 경로로 가져온다. `outputs/encounters-v1/` 폴더만 서버로 열거나 `file://`로 열면 모델 로딩이 실패할 수 있다. Three.js와 실행 코드는 로컬 HTML에 번들하고, 모델은 기존 함대 파일을 공유한다. 외부 CDN이나 생성 API를 사용하지 않는다.

빌드는 `outputs/encounters-v1/index.html`, 결과 `catalog.json`, 자산 참조·해시를 기록한 `manifest.json`을 만든다. `README.txt`는 사용 안내다. 검사 결과와 검사 화면은 `work/verification/encounters/`에 저장한다. 패키지 명령의 변경은 루트 `package.json`을 기준으로 확인한다.

## 조작과 흐름

| 입력 | 동작 |
|---|---|
| WASD / 방향키 | 이동 |
| 마우스 왼쪽 누르기 / J | 누르는 동안 사격 |
| Space | 긴급기동 |
| 자동 조준 설정 | 켜면 가까운 적을 조준하고, 끄면 마우스 위치로 조준 |
| Esc / 일시정지 버튼 | 전투 시간·이동·적 공격 정지/재개 |
| 터치 조이스틱 / 사격 / 기동 | 모바일 이동·사격·긴급기동 |
| 다시 출항 | 현재 판 처음부터 재도전 |

각 판은 `일반 적 → 중간보스 → 안전 정비 → 후반 일반 적 → 최종보스 → 승리` 순서다. 중간보스 뒤에는 위험 요소를 정리하고 선체를 완전 수리한다. 사용자가 ‘후반 항로로’를 눌러야 전투가 재개된다. 이 무료 완전 수리는 이번 교전 시험을 위한 구제 장치이며, 정사 경제·수리 비용·항구 거래를 구현한 규칙이 아니다. 선체 체력이0이 되면 패배하고 같은 판을 처음부터 재도전할 수 있다.

판별 ‘확보 완료’ 표시는 브라우저 `localStorage`의 `cloudstitch-encounters-v1-wins`에 저장한다. 전투 중 위치·체력·부품·자원·캠페인 진행을 이어하는 저장은 없다. 저장 실패 안내가 나와도 현재 플레이는 계속된다. 브라우저와 로컬 서버 주소/포트가 달라지면 승리 표시가 공유되지 않는다.

## 6개 판과 편성

| 판 | 전반 / 후반 일반 적 | 중간보스 역할 | 최종보스 역할 |
|---|---:|---|---|
| 1 종항 잔해해역 | 2 / 2 | 소형 장례 경비선 · 봉쇄 | 종을 삼킨 자 · 종/충격파 |
| 2 청록빛 상승기류 협곡 | 3 / 3 | 협곡 관문 지휘정 · 포격 | 사슬협곡 인양 지휘선 · 작살/견인 |
| 3 천둥 폭풍벽 | 3 / 3 | 폭풍 견인대장 · 작살/견인 | 폭풍 봉쇄 지휘선 · 봉쇄 |
| 4 쇠갈비 공업지대 | 3 / 4 | 도크 수리 지휘정 · 수리 | 수석 조선공의 지휘함 · 도크/압력 |
| 5 이름 없는 함대의 저층 안개 | 3 / 4 | 안개 돌격대장 · 돌진 | 죽은 함대 왕의 배 · 함대 지휘 |
| 6 황궁 검은 천정 | 3 / 3 | 황궁 외곽 종 관문함 · 종/충격파 | 마지막 들숨 · 봉인 심장/압력 |

총 일반 적36회, 중간보스6회와 최종보스6회로48회 등장한다. 이는 여섯 판의 스폰 합계이며 고유 모델48종이나 정사 함선48척을 의미하지 않는다. 일반 편대는 한 구간 최대4척이다. 정찰·봉쇄·인양·수리·돌진·기습·포격·화염·종·조선소·함대왕·심장의12가지 교전 역할을 조합한다. 판별 실제 자산 ID와 근거는 [catalog.json](catalog.json)을 확인한다.

원문 `08-world-map.txt`에는 지역6개, `33-level-layouts.txt`에는 기본 전장L1~L6가 있지만 서로1:1 대응하지 않는다. L6는 종항 외곽 방어이며 황궁은 `43-final-boss-encounter.txt`를 별도로 참고했다. 전체 정사 전장 수는 미정이다. 각 판에 두 보스를 배치한 것은 이번 사용자 요청에 맞춘 제작 구성이다.

## 정사와 시제품의 경계

모든 보스 슬롯의 `sourceKind`는 `prototypeCommander`다. 정사 이름·외형이 있는 보스도 여기서는 **정사 외형을 참고한 교전 역할 변형**이며 `canonEncounterCompleted:false`로 기록한다. 보스의 전체 장치 기믹·대사·기억 반환·구조·결말을 완성하지 않았다. 체력0은 이번 전투의 무력화 판정이며 정사 선장의 사망을 확정하지 않는다. 함대왕 원문의 기억/연결부 목표나 황궁의 봉인·세 결말을 단순 격파로 대체하지 않는다.

3단계 난이도의 이름은 `111-difficulty-assistance.txt`를 참고한다. 체력·피해·예고 배율은 이번 시제품 가설이며 정사 출시 밸런스가 아니다.

| 난이도 | 적 체력 | 적 피해 | 예고 시간 |
|---|---:|---:|---:|
| 여유로운 항해 | 0.85 | 0.7 | 1.2 |
| 표준 항해 | 1 | 1 | 1 |
| 거친 항해 | 1.2 | 1.2 | 1 |

모든 난이도에서 돌진 예고 최소1.2초와 광역 예고 최소1.5초를 유지한다. 큰 공격 예고 토큰은 전반/중간보스1개, 후반/최종보스2개다. 역할 조합·회복 틈·장치 패턴으로 판별 차이를 시험하며 최종 재미·난이도 검증과 구분한다.

이번 범위에는 모듈 연결부 절단·하위 묶음 분리·회수·소유권·화물·제작·장착·양력/전력/연료·정산·안전 경계 저장이 없다. `67-playable-slice-priorities.txt`의 P1~P4 순환과 전체 캠페인은 후속이다. 이동·사격이 있는 이 브라우저 시제품과 정식 엔진 프로젝트 채택을 구분한다. 모델의 화면상 크기와 XZ 월드 단위도 미터·기획U·최종 엔진 스케일 확정이 아니다.

## 소스와 검사

| 파일 | 역할 |
|---|---|
| `catalog.json` | 6개 판, 기존 함대 자산 ID, 원문 근거, 편성·역할·환경·난이도 가설 |
| `core.js` | 고정 시간 간격 전투, 상태 전환, 피해/투사체/공격 예고·패배·재도전 |
| `scene.js` | 기존 GLB 로딩·복제, 손그림 전장, 모델 동작·공격 경계·효과 표시 |
| `app.js` | 키보드/마우스/터치, 메뉴·HUD, 일시정지, 판별 승리 표시 저장 |
| `template.html` | 반응형 한글 화면 |
| `build.cjs` | 로컬 번들, 결과 카탈로그·참조 manifest 생성 |
| `../qa/encounters.cjs` | 실제 코어 및 번들된 브라우저의 판 전환·전투·입력·레이아웃 검사 |

`node tools/qa/encounters.cjs --core-only`는 코어 부분 검사다. 전체 브라우저 검사와 혼동하지 않는다. 최종 결과는 실제 검사 JSON과 빌드 manifest를 다시 확인한다. 기존 함대의 구조/리깅 QA 통과도 이번 전투 흐름·입력·성능 검사와 별도다.
