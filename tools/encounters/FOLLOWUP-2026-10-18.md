# Cloudstitch 실제 항해 접합 후속 검토

후속 준비 버전 `encounters-integration-v2`. 최초 v1 인계는 그대로 보존하며, 이 문서는 2026-10-18 사용자의 통합 실제 항해 결과 확인 요청에 따른 추가 기록이다.

## 실제 항해 결과의 범위

통합 담당이 첫 왕복을 실제 이동/사격/인양 입력으로 통과했다고 전달했다. 195step×0.05초, 사격19·명중19, 부품분리1·인양1·귀환정산1·피해9이며 teleport/강제damage를 사용하지 않았다. 이것은 첫지역 opening에서 회수 후 철수한 왕복이며 보스 전체 완주가 아니다. 정식 보고서 예정 경로는 `outputs/integration-v1/verification.json`이다. 최초 후속 확인 시 그 파일은 아직 없었고 두 항해/개조/저장복원/브라우저 QA는 통합 담당이 진행 중이었다.

이후 실제 `outputs/integration-v1/rules-verification.json`을 읽어 입력 기반 왕복2회, 개조, 저장 후 새 controller 복원, 정산 중복 방지, 일시정지, 저장 실패/손상/충돌 처리의6검사 통과를 확인했다. 두 항해 모두195step·사격19·분리/인양 각1회였고 정산2개, 설치6부품, 창고5부품을 확인했다. 이것은 브라우저 QA와 별도의 headless 통합 검증이다.

## 재현한 접합 문제와 담당 경계

1. **전반 공격 예산 미적용.** `createVoyageController→depart→advance(1/60,{})`를126step 수행하면 time2.10초의 opening에서 director 예산1인데 실제 enemy.telegraph가2개였다. 통합 controller가 모든 적에게 공격 대상을 전달하고 예산 메타데이터를 실제 시작 제어에 사용하지 않았다.
2. **패배 clear 미소비.** 상태 배치 재현에서 패배 후 적2·예고1과 미승인 clearance가 남았다. session defeat 분기에서 director.playerDefeated 뒤 drainDirector를 생략한 접합 문제다.
3. **보스 표시 정보 누락.** 스폰된 sim 적의 tier/role이 undefined여서 renderer의 보스 라벨 판별이 실패했다.
4. **단계별 스폰의 플레이어 중첩.** 강제 opening격파 후 플레이어를 기존 후보(-32,-16)에 배치한 재현에서 midboss가 같은 좌표에 출현했다. 최초 safe:true 후보를 현재 상태 재검사 없이 재사용한 문제다.

2~4는 실제 입력 왕복 통과와 별개인 메모리 상태 배치/강제격파를 사용한 접합 검사다. 다른 담당의 controller/전장/월드 파일은 수정하지 않았고 통합 담당에게 정확한 재현과 수정 제안을 전달했다.

## 공격 예산 보조 함수

새 `attack-budget.mjs`는 다음 순수 함수만 제공한다. 두 번째 전투·타이머·피해/이동 상태를 만들지 않는다.

```js
allocateAttackTokens({
  units: [{ enemyId, warningActive: true, ready: false }],
  maxTokens: director.snapshot().majorAttackTokens,
});
// {permittedEnemyIds,activeWarnings,admittedStarts,maxTokens,
//  exceededByExistingWarnings,authority}
```

진행 중 실제 경고를 먼저 예약하고, 남은 슬롯에 준비된 적만 허용한다. 기존 호스트 상태가 이미 상한을 넘었으면 이를 보고하며 경고를 중간에 몰래 지우지 않는다. clear/정비에서 경고가 남아 있다면 호스트의 clear를 고쳐야 한다.

현재 battlefield의 updateEnemy는 `attackTarget=null`이면 cooldown 차감 전에 돌아가는 구조였다. `ready:e.cooldown<=0`을 적용하려면 **battlefield 소유 코드에서** cooldown 감소를 그 early return 앞에 두어야 한다. controller/helper에서 cooldown을 별도로 차감하지 않는다. 변경 없이 대상을 차단하면 초기 cooldown이 줄지 않아 적 사격이 영원히 멈출 수 있다. 이 주의점도 통합 담당에게 전달했다.

`attack-budget.test.mjs`의 정책 검사6개와 기존 director 검사16개, 합계22개를 통과했다. 명령은 `node --test tools/encounters/attack-budget.test.mjs tools/encounters/director.test.mjs`다. 이는 보조 정책 검사이며 실제 controller 수정 후 단일-sim 예산/사격 재개와 전체 왕복 재검증을 대신하지 않는다.

현재 공유 battlefield에서 cooldown 위치 보완을 확인한 뒤 `node --test tools/encounters/attack-budget-host.test.mjs`의3개 검사도 통과했다. 대상 차단 중 cooldown이 .1초 정확히 감소하고, 같은 sim의8초 구간에서 예산1/2 각각 최대경고1/2를 유지하며 두 적 모두 실제 발사했다. fixture 스폰을 사용했고 강제피해/격파는 없었다. 새 보조 함수+기존 계약+실제 단일-sim 회귀의 확인 합계는25개다.

## 인계 상태

보조 함수와 정책 검사는 준비 완료다. 통합 controller 적용 후 재검증은 진행 중이다. v2의 최신 실제 검증 상태와 파일 해시는 `outputs/encounters-integration-v2/verification.json`, `source-manifest.json`에 기록한다. v1의 파일 표는 최초 인계 시점의 역사 기록으로 유지한다.

## 최종 접합 재검증 완료

위의 대기 상태는 v2 보조 함수 최초 전달 시점의 기록이다. 이후 통합 담당이 `battlefield-authority-0.2.1`을 반영한 최신 통합 공간에서 `attack-budget-host.test.mjs` 3개를 다시 실행해 모두 통과했다. 실제 controller를10초 진행한 재현에서는 opening 예산1·최대예고1, 두 적 모두 실제발사, 플레이어 HP73으로 공격이 멈추지 않음을 확인했다. 이전 root 공간의 cooldown 불일치는 해소됐다.

같은 메모리 재현으로 나머지3건도 해결을 확인했다. 패배 시 clearance 승인 완료·적0·예고0·탄체0이며 retry는 HP100/opening 적2로 돌아온다. 플레이어(-32,-16) 위치에서 중간보스는(28,-27), 거리61 떨어진 후보를 사용했다. 후반·최종보스도 겹치지 않았다. sim 적에 scout/normal, blockade/midboss, bell/finalboss 정보가 전달돼 보스 표시 판별이 가능하다. 정비/승리 정리도 정상이다.

최종 확인 기록은 `outputs/encounters-integration-v2/controller-recheck.json`, 최신 담당 파일 SHA는 `final-manifest.json`이다. 최초 v1/v2 manifest는 각 전달 시점의 기록으로 보존한다. 통합 담당의 입력 기반2왕복 보고서를 대조했으며 브라우저 지속/잔상/모바일/Edge QA는 통합 담당이 별도로 진행 중이다. 이 담당은 그 브라우저 검사나 전체보스 실전승리를 수행/인증했다고 기록하지 않는다.
