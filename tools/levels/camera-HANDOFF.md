# Cloudstitch 항해 시점 비교

2026-10-18. 사용자의 “카메라 뷰가 너무 위에서 정면으로 내려다 보는데 다른 뷰는 어떨까” 요청에 따른 비교 시제품이다.

## 실행과 범위

`outputs/playable-camera-v1/index.html`을 기존 로컬 outputs 서버에서 연다. 기본 서버는 `node tools/levels/playable-serve.mjs`, 주소는 `http://127.0.0.1:8860/outputs/playable-camera-v1/index.html`이다.

기존 `outputs/playable-battlefield-v1/` READY-3와 소스25파일은 보존했다. 새 소스는 `tools/levels/camera-*`다. 새 저장 키는 `cloudstitch.camera-study.v1`이므로 기존 플레이 저장과 분리된다. `playable-session.mjs`와 sim/encounters/harbor/save를 그대로 재사용한다. 신규 원화·모델·음향·배포·패키지 설치는 없다.

## 비교할 시점

| 버튼 | 고도 / 방위 | 용도 |
|---|---|---|
| 낮은 사선 · 추천 | 32° / 35° | 선체 옆면과 갑판, 주변 전투 공간을 함께 읽는 기본 후보 |
| 측면에 가깝게 | 20° / 65° | 배의 옆모습과 부유섬 깊이를 보는 감상 후보 |
| 기존 높은 시점 | 55° / 0° | 원래 높은 방향과 비교. 시야 맞춤은 새 회전 기준을 공통 적용 |

세 시점 모두 정사영이다. `V` 또는 버튼으로 전환한다. `멈춰서 비교`는 controller의 pause 명령으로 전투를 멈추고 비교 중에만 큰 일시정지 패널을 감춘다. `비교 마침`은 진입 전 일시정지 상태를 복원한다. 전환은 이동·사격 held 상태를 비우고 자동 조준으로 돌아간다. `M`은 기존 항로 전체 보기이며 전체 보기 중에는 높은 방위0°와 화면 기준 이동을 사용한다.

카메라의 방위에 맞춰 키보드/터치의 화면 방향 입력을 변환한다. 원래 입력을 먼저 정규화하므로 대각선 속도·방향이 축별 clamp 때문에 왜곡되지 않는다. 변환 결과를 누적하지 않는다. 조준은 마지막 커서의 화면 좌표를 현재 카메라에서 매 입력 tick 다시 지면으로 투영한다. 기존 QA pilot는 월드 입력을 그대로 사용한다.

자동 프레이밍은 worldX/worldZ 고정축 대신 카메라의 right/up 축으로 플레이어와 가까운 적을 투영한다. 표식은 실제 DOM 크기와 안전 여백8px를 유지한다. `OutlineEffect.autoClear=true`도 유지한다.

## 검증

`node --test tools/levels/camera-profiles.test.mjs` 4/4 통과: 모든 시점의8방향/대각선 속도, 직교 축과 거리, 좁은 화면 프레이밍 범위, 반복 전환에서 원래 입력 보존.

기존 three 의존성으로 `node tools/levels/camera-verify.cjs` 5/5 통과: 세 시점의 지면 위치→화면→raycast 왕복 오차1.6e-14 이하, UI69ID/64참조 연결, 기존READY-3의25파일 SHA 전부 동일. 빌드는 `node tools/levels/camera-build.cjs`다. 새 의존성 설치는 없다.

기존 사용자 IAB 한 탭에서 출항→제품 pause 비교→세 버튼 전환을 확인했다. 같은 장면의 `oblique.jpg`, `side.jpg`, `high.jpg`를 저장했다. 비교 중 선체100/100·항해00:00을 유지했고 큰 pause 패널 대신 시점 비교 컨트롤을 표시했다. 사선은 선체·갑판, 측면은 옆 실루엣을 실제로 확인했다. 섬의 가림이 있는 것도 확인했으므로 자동 투명화를 주장하지 않는다.

390×844에서 scroll390×844로 페이지 넘침이 없고 시점 버튼3개, 하단 비교 패널이 x23..378/y701.5..820으로 화면 안에 들어왔다. 멈춘 이동·사격UI는 비교 중 감춰 배를 가리지 않는다. `mobile.jpg`에 저장했다. 오류/경고 console 로그0이며 화면 크기는 원래대로 복원했다. 실제 마우스 사격/명중·두 왕복·실패 복구 전체 회귀는 새 카메라에서 수행하지 않았고, 커서 투영은 위 Node 수학 검사 범위다. 이전 버전의 전체 전투 QA를 새 카메라의 통과로 복사하지 않는다.

## 한계

시점 선호와 인간 플레이 가독성은 사용자 비교가 필요하다. 낮은 측면은 전후 거리가 압축되고 섬 뒤에 배가 가려질 수 있다. 절차적 섬/건물은 하나로 합쳐진 메시여서 모든 섬을 개별 자동 투명화하는 기능은 없다. 이 비교는 카메라 후보이며 정식 카메라 확정·전체 캠페인 완성이 아니다.
