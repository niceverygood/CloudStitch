80. 미션 실패와 복구 — 다음 시도를 이해하는 화면
상태:19번 위험 대응·45번 저장·66번 정산·73번 철수 계승. 게임 구현·저장 장애 실험은 미실시다.

서로 다른 세 사건
전투 패배: 핵심 선체 파괴 또는 임무 실패 조건 충족. 마지막 안전 체크포인트의 부품·자원·조사 상태로 복원한다. 자발적 철수: 현재 확정된 회수·구조·조사를 보존하고 미완료 보상은 지급하지 않는다. 저장 오류: 현재 세션 상태와 마지막 성공 저장을 구분해 안내한다. 저장 오류를 세계관의 저주나 전투 패배처럼 연출하지 않는다.

위험 직전의 복구
양력 부족은 투하·수리·보조 부양 대응, 엔진 상실은 비상 이동·구조 요청 또는 재시도. 실제 위험 타이머는 일시정지 메뉴에서 멈춘다. 경고 화면을 읽는 동안 배가 더 빨리 추락하지 않는다. 큰 분리 사고 직후 최소 대응3초, 일반7초 초기 유예는19번 가설을 따른다.

패배 화면
짧은 선체 손상 정지 장면 뒤 charcoal 화면. 제목 ‘다시 항해하기’. 원인은 확인된 것만 한 문장: ‘핵심 선체가 파괴되었습니다’, ‘양력이 부족한 상태를 회복하지 못했습니다’. 모르는 원인을 적 이름이나 임의 조작 실수로 추정하지 않는다. 최근 큰 피해 출처·잃은 기능을 선택 상세로 제공하되 긴 전투 로그를 강제하지 않는다.
버튼: ‘체크포인트에서’, ‘준비 다시 보기’, ‘메뉴로’. 기본 포커스는 체크포인트. 도움말 링크는 실패 원인과 맞는 한 항목만 우선한다. 비난·조롱·유료 부활·임의 희귀품 손실은 없다. 재시도는 소비품과 탄환 자원을 체크포인트 상태로 되돌린다. 물리 프레임 전체를 정확하게 복원한다는 약속은 하지 않는다.

체크포인트 설명
구역 이름·저장 시점·복원되는 함선 상태를 표시한다. 해당 지점 이후 미확정 회수품·자원 사용·조사 진행이 되돌아간다는 범위를 짧게 알려 준다. 이전 안전 경계에서 이미 정산된 보상을 되돌리지 않는다. 패배 때마다 다른 무작위 적 조합을 강제로 새로 뽑지 않고 원인 학습이 가능한 배치를 우선한다.

보스 구조 단계
10번 첫 보스의 마지막45초 구조 실패는 구조 시작 지점으로 복원한다. 끝난 보스3단계 전체를 반복하지 않는다. 화면에 ‘구조 단계부터 재시도’라고 명시한다. 접근성·난이도 조정으로 타이머를 바꾸는 후보는 별도 설명하며 실제 옵션값은 테스트 후 정한다. 실패 컷신에서 주민 사망을 반복 재생하지 않는다.

준비 다시 보기
패배 화면에서 장착 미리보기·조작 도움·위험 예고 설명에 접근한다. 현재 지점에서 장비 교체를 허용할지는 보관함 접근 조건을 따른다. 모든 현장 체크포인트에 항구 전체 상점을 순간 소환하지 않는다. 허용되지 않으면 안전 항구 저장으로 돌아가는 별도 선택과 복원 범위를 안내한다. 확인 전 현재 저장을 덮어쓰지 않는다.

저장 오류
메시지 ‘저장하지 못했습니다’. 선택: 재시도, 현재 세션 계속, 마지막 성공 저장 확인. 저장 경로 권한·공간 부족·파일 충돌의 확인된 원인만 표시한다. 실제 원인을 모르면 ‘원인 확인 필요’로 쓴다. 마지막 저장 시간은 실제 데이터에서 읽는다. 실패한 저장을 성공 체크 아이콘으로 표시하지 않는다. 저장 중 종료 요청은 상태를 안내하고 무한 대기시키지 않는다. 기술 구현 방식은 개발 환경 확정 뒤 설계한다.

검수
패배와 철수를 구분하는가? 어떤 자원이 돌아오는지 이해하는가? 보스 구조 재시도 지점이 정확한가? 오류 상태에서도 입력·뒤로 가기·메뉴가 작동하는가? 이 문서는 향후 검수 시나리오이며 실행 결과가 아니다.
