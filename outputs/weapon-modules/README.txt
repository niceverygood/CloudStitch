Cloudstitch · 클라우드스티치
손그림 인상의 실제 3D 장착 무기 제작
기준일: 2026-10-18

작업 목적
현재 선택 비행선의 청록 금속·황동·꿀빛 목재·크림 천·산호색 수선 포인트를 이어받는 단계1 기본 무기 여섯 종을 제작한다. 한 작업에서 한 무기의 기준 그림과 실제 3D 모델을 만들고 검사한 뒤 다음 종류로 진행한다.

제작 순서
1. 기관총 / Machine Gun: 짧고 가는 단일 천공 포신, 작은 측면 급탄함.
2. 함포 / Deck Cannon: 길고 굵은 단일 포신, 큰 후미 약실과 반동 레일.
3. 박격포 / Mortar: 가파르게 위를 향하는 짧은 튜브와 삼각 각도 받침.
4. 작살포 / Harpoon Launcher: 굵은 작살 머리, 감긴 케이블과 눈에 보이는 윈치.
5. 사슬탄 발사기 / Chain-Shot Launcher: 짧고 넓은 포구, 사슬로 이어진 두 탄구의 옆 랙.
6. 화염방사기 / Flamethrower: 짧은 노즐, 차단 밸브·호스·낮은 연료통.

이번 범위는 각 종류의 단계1 한 개다. 단계2~4 강화형, 쌍열·이중 작살 등 추가 변형은 포함하지 않는다. 외형·역할은 outputs/21-weapons-combat-roles.txt와 outputs/72-weapon-mount-readability.txt를 따른다. 무기 개별 수치·경제 규칙을 새로 만들거나 이미지의 숫자를 명세로 채택하지 않는다.

시각 기준
outputs/selected-airship-toon3d/reference.png의 채색과 제작 감성을 따른다. 광택 나는 현실 군용 금속보다 넓은 붓 자국, 단순한 명암, 짙고 읽기 쉬운 윤곽선이 중요하다. 3D로 회전할 수 있으면서 정지 화면은 손으로 그린 그림처럼 보이는 것을 목표로 한다. 천 수선과 산호 포인트는 후부 손잡이·패드 등 작은 곳에 사용해 무기의 기능 실루엣을 남긴다. 뜨거운 포신과 포구에 천 감개를 놓지 않는다.

공통 장착 외형 제안
기획 원안은 낮은 청록 원형 회전링, 황동 잠금 핀, 꿀빛 목재 사각 보강판이었다. 실제 제작 아트에서는 비행선과 어울리는 원형 목재 받침으로 변형했다. 사각판의 B 비율은 원안의 상대적인 크기 제안으로 보존하며, 원형 받침을 사각판 규격과 정확히 일치한다고 해석하지 않는다. 무기별 받침과 포신·작업 장치의 형태를 바꿔 종류를 구분한다. 현재 제작 범위는 갑판 회전대 외형이며 측면 거치대와 구조 부모를 갖는 외부 갑판 모듈은 후속 범위다.

production-spec.json은 B=목재 보강판의 한 변으로 상대 비율을 제안한다. B는 미터나 기획 거리 U가 아니며 게임 소켓의 확정 치수가 아니다. 부품별 목표와 피벗의 이름·위치도 후속 편집을 위한 제안이다. 생성 GLB가 실제로 분리된 메시·장착 원점·조준축을 가진다고 가정하지 않는다.

보는 방법
gallery.html은 제작 결과의 손그림 렌더·기준 그림·GLB 링크를 모은 목록이다. index.html은 실제 GLB를 회전·확대하는 무기 작업대이며, 무기 선택 목록과 URL의 ?weapon=무기ID로 개별 모델을 볼 수 있다. 로컬 브라우저에서 연다. 생성 기준 PNG는 정지 그림이고, 작업대 화면은 실제 3D 모델을 그린 것이다.
Cloudstitch-weapons-6.zip을 풀어 gallery.html 또는 index.html을 열 수 있다. index.html에는 선택 비행선과 무기·뷰어 코드가 내장되어 ZIP 밖의 파일이나 인터넷 없이 표시된다. catalog.json으로 작업대를 다시 빌드하려면 저장소의 tools/와 원본 selected-airship-toon3d/airship.glb도 필요하다. ZIP은 완성 산출물 묶음이며 전체 소스 저장소의 대체물이 아니다.

표시 모드 세 가지
- 손그림: 조명 반사보다 생성 텍스처의 채색과 선을 중심으로 보여준다.
- 셀 명암: 단순한 단계별 명암으로 3D 볼륨을 보여준다.
- 원본 재질: 생성된 GLB의 재질을 보여준다.

윤곽선과 선 두께를 바꿀 수 있으며 처음 시점·화면 맞춤·자동 회전, 드래그 회전·휠 확대·오른쪽 드래그 이동을 제공한다. 손그림·셀 명암·윤곽선은 작업대의 런타임 표현이다. 원본 GLB를 다른 엔진에 가져가는 것만으로 같은 셰이더가 자동 재현되지는 않는다. GLB 다운로드는 생성 원본 모델이며 작업대의 화면 효과를 보편적인 엔진 재질로 굳힌 파일이 아니다.

장착과 구현의 구분
선택 비행선 GLB는 단일 메시이며 기존 포탑이 선체에 포함되어 있다. 기존 비행선 원본을 잘라내거나 기존 포탑을 교체하지 않고 보존한다. 새 무기의 메시·재질·삼각형·애니메이션 여부는 각 manifest.json에 실제 검사값으로 기록한다. 생성 결과가 단일 메시이면 외형상 구별되는 포신·회전대·윈치·호스도 독립적으로 움직일 수 있는 부품으로 완성된 것은 아니다.

작업대의 '장착 배치'는 선체 옆 외부 갑판 위치를 가정해 크기·색·방향을 비교하는 표시다. 방향과 크기 조절은 화면 배치 조절이며 실제 게임 소켓 선택이나 포탑의 독립 조준축이 아니다. 기존 포탑 위에 새 무기를 겹쳐 놓거나 선체 옆에 놓은 모습을 최종 소켓 장착 완료라고 부르지 않는다. 외부 갑판 가설 배치는 부모 골조·하위 모듈 분리·중량·전력 규칙까지 구현한 장착도 아니다.

선체의 기존 무기 분리, 새로운 무기 부품 분리, 실제 크기와 장착 원점, 피벗, 자기 기낭과의 충돌·포각, 발사점, 충돌체·LOD·엔진 재질·애니메이션은 후속 작업이다. 모델 전체 회전과 자동 회전은 뷰어 카메라 기능이며 무기 작동 애니메이션이 아니다.

사격·장전·과열·반동·곡사·케이블 장력·인양·사슬 상태 효과·화염 피해는 아직 구현하지 않았다. 무기 모델과 회전 미리보기는 전투 게임 빌드가 아니다. 모델을 돌릴 수 있다는 사실은 무기의 360도 사격을 허용한다는 뜻이 아니다.

파일과 기록
production-spec.json: 여섯 종의 디자인·제작 순서·역할·예상 부품·후속 피벗·한계. 생성 전에 작성한 기획을 보존하고 실제 제작 차이는 별도 결과 기록과 함께 읽는다.
progress.json: 요청한 순서, 실제 완료 목록·남은 항목·다음 추천, 제출 작업과 보고된 비용의 진행 기록. 폴더가 있다는 사실만으로 완료를 세지 않는다.
delivery-summary.json: 이번 기본6종 완료 집계, 실제 모델 수치·90크레딧·마지막 잔액·파일/뷰어 검사 범위와 다음 추천 작업. package-manifest.json은 ZIP 항목과 SHA256 확인 목록이다.
catalog.json: 작업대와 갤러리에 수록한 자산의 파일·역할·상태·배치 제안·한계.
각 무기 폴더의 manifest.json: 실제 Meshy 작업ID·operation ID·보고된 사용 크레딧, 파일 크기·SHA256·삼각형·메시·재질·텍스처·애니메이션과 뷰어 검사 결과. 실제 자산 수치와 작업 이력은 이 파일을 사실 기준으로 삼는다.
reference.png / reference-prompt.txt: 생성 기준 원화와 실제 제작 프롬프트.
weapon.glb: 생성 원본 실제 3D 모델. meshy-render.png는 생성 도구의 렌더다.
preview-handdrawn.png / preview-cel.png / preview-original.png: 작업대 세 표시 모드의 렌더.
preview-mounted.png: 선체와 함께 보는 외부 갑판 가설 배치 렌더.

이 안내에는 계속 바뀌는 완료 개수·삼각형 합계·비용 합계를 고정하지 않는다. 개별 성공·검사 상태는 manifest.json, 전체 진행과 비용 합계는 progress.json 및 최종 합산 기록을 따른다. completed_asset_prototype는 3D 외형 원형과 해당 뷰어 검사가 완료됐다는 뜻이며 전투 자산의 모든 후속 제작이 끝났다는 뜻이 아니다. planned 항목을 실제 모델 완료에 포함하지 않는다. 보고된 작업 크레딧은 기록된 도구 응답이며 실제 계정 잔액 차이를 별도로 확인했다면 그 근거도 함께 읽는다.

검수 기준
- 한 번에 한 무기만 만들고, 기준 그림에서 인물·선체·발사 효과·문자·다른 변형을 제외한다.
- 실제 GLB를 읽어 크기·삼각형·메시·재질·텍스처·애니메이션을 기록한다.
- 단일 메시이면 단일 메시라고 적고, 부품 분리·리깅·소켓 제작을 완료했다고 주장하지 않는다.
- 전면·측면·후면·사선 탑다운의 형태와 여섯 종 간 식별성을 확인한다.
- 손그림·셀 명암·원본 세 표시 모드와 윤곽선, 회전·확대, 잔상 재발을 검사한다.
- OutlineEffect.autoClear=true를 유지한다. GLB 자체에 셀 셰이딩과 윤곽선이 엔진 공통 기능으로 저장되는 것은 아니다.
- 파일 검사와 뷰어 테스트를 게임 성능·재미·밸런스 검증으로 표현하지 않는다.

원본 보존·Git
기존 비행선·기획·시작화면은 보존한다. API 키와 인증 정보는 저장하지 않는다. PNG·GLB는 .gitattributes의 LFS 규칙을 따른다. ZIP과 work/중간 파일·node_modules는 기본적으로 Git에 넣지 않는다. Git push는 별도 사용자 요청 범위에서 수행한다.
