제작 방식
hero6개의 build_method는 hero_meshy다. 순서는 harbor-inn → repair-workshop → canvas-market → harbor-office → beacon-lighthouse → memory-observatory다. 한 건물의 기준 이미지·실제 Meshy 모델·외형/구조 검토를 마친 뒤 다음 건물로 진행한다. 목표는8,000삼각형과2048×2048 텍스처이며 실제 결과를 보장하는 수치가 아니다. 생성된 건물은 한 메시일 수 있고 내부·문·창·리프트·관측 장치가 독립 부품이나 작동 리그로 나뉜다고 가정하지 않는다.

나머지90개의 build_method는 local_mesh다. 기존 팔레트와 형태를 잇는 독창적 상세 모듈형3D를 로컬 제작한다. 판재·보·고정띠·곡면·단차·고리·둥근 캡·수선 조각처럼 가시 부품과 재료를 갖춰야 한다. 단순 큐브 하나나 단색 원기둥 목업만으로 상세 게임 자산을 완성했다고 주장하지 않는다. 부품 수와 삼각형 수를 늘리는 것 자체가 품질·성능의 근거도 아니다. 실제 결과의 구조와 기본 시점 식별성을 함께 검사한다.

명세 작성 자체는 새 이미지/모델 생성·모델 수정·외부 연락을 수행하지 않는다. hero 실제 생성은 별도 담당 작업으로 기록한다. local90에 추가 유료 Meshy 생성이나 이미지 생성을 자동으로 추가하지 않는다. 실제 비용은 개별 생성 응답과 manifest를 따른다.

아트 방향
크림 캔버스, 청록 지붕과 기계, 꿀빛 목재, 황동 창틀·고정띠, 작은 산호 수선 포인트를 공통으로 사용한다. 깊은 틈과 폭풍·후반 덧댐은 남청으로 정리한다. 둥근 지붕 끝, 부드러운 판재 모서리, 두께 있는 로프와 고리, 넓은 채색 면을 우선한다. 사실적인 PBR 광택·현대 군용 금속·다른 작품의 고유 휘장이나 캐릭터를 복제하지 않는다.

지역 구분은 새 지역명보다 재료·실루엣·생활 소품으로 만든다. 협곡은 청록 광물과 매단 다리, 폭풍은 낮은 조명·두꺼운 방풍 천, 공업지대는 큰 곡선 철골과 공구, 저층 안개는 오래된 등대와 작은 계류등, 황궁 외곽은 크림 석재·황동·남청 봉인 덧댐이 중심이다. 도형의 색이 실제 위험 판정·시야 차단·낙뢰·강풍을 결정하지 않는다.

상대 크기와 연결 이름
모든 자산은 +Y 위, +Z 정면, +X 오른쪽을 제안한다. 바닥 또는 부착면 중앙을 후속 원점으로 삼되 실제 생성 GLB의 원점·축·크기는 결과에서 측정한다. relative_scale_only=true와 D 비율은 비교용 아트 가설이다. 실제 미터, 기존 기획 거리U, 게임 소켓 치수, 통로 최소 폭, 배의 최대 크기로 환산하지 않는다.

optional_connector_names의 dock-front, wall-left, entry-front, interact-front, rope-anchor 등의 이름은 조립 기준점 제안이다. 이름만으로 실제 엔진 소켓·부모 연결·충돌·통행·상호작용이 완성된 것은 아니다. 실제 연결점을 구현했다면 좌표·축·호환 규격을 결과 기록에 따로 적는다. 문/창/뚜껑의 parts 목록도 가시 외형 목표이며 독립 움직임·개폐·건물 내부를 보장하지 않는다.

기능과 외형의 구분
collider, navmesh, LOD, interior, interaction은 이번 명세에서 not_implemented다. 수리대·연료 보급기·인양 크레인·승강판이 실제로 움직이고 자원을 바꾸는 장치로 완성된 것은 아니다. 호환되는 메뉴와 걷지 않고 접근하는 항구 기획, 저장·정비·보관·항로 기능은 실제 엔진 구현이 별도로 필요하다. 소품의 상자·연료통·스크랩이 실제 인벤토리·전리품·새 재화 규칙을 만들지 않는다.
