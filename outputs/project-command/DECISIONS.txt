D02. 최신 사용자 요청이 담당의 새 범위
함대 채팅의 최신 요청은 적·보스·주인공이 서로 다른 특징을 갖도록 외형을 개선하는 것이다.
지도 채팅의 최신 요청은 ‘전장 제대로 구현해줘’다. 단순 공간 미리보기로 축소하지 않는다.
단, 기존 전투 상태를 재사용하는 플레이 화면·공간으로 구현하고 원본·완료본을 보존한다.
새 VFX는 BRIEF와 사용자 첨부 원본 기준의 Meshy 아트 제작이다. 기존 전장 런타임의 소유권과 구별한다.

D03. 통합 위치 구분
공유 checkout에 integration 폴더가 없는 것만으로 전투 미구현이라고 판정하지 않는다.
통합 담당이 별도 worktree에서 한 항해를 실제 검증했다. local-locations.json은 이번에 존재를 확인한 위치이며 타PC 경로를 가정하는 문서가 아니다.
통합 담당이 위치 안내·선별 인계 절차를 작성한다. 총괄이 전체 복사·pull·reset으로 공용 수정 사항을 덮어쓰지 않는다.

D04. 단일 상태·소유 폴더
battlefield: 이동·시간·HP·탄·피해·절단·회수·화물·승패.
encounters: 편성·스폰 요청·공격 의도·예고·단계 진행.
예고 명세·의도는 encounters, 실제 telegraph 상태·시간·발사는 battlefield가 소유한다.
levels: 시각 배치·충돌/스폰 후보·귀환/상호작용 위치·플레이 화면의 연결.
harbor/shipyard/save: 소유권·창고/장착·수리/정산·안전 저장.
combat-vfx-v2: 새 메시/텍스처·클립·효과 레시피/비교 아트.
integration: 공용 어댑터·실행물·package/lockfile·설치·서버·무거운 QA.
총괄: outputs/project-command/의 현황·결정·교차 검토. 구현 담당 코드를 대체하지 않는다.

D05. 새 전장 출력 경로 정정
총괄의 최초 메시지는 outputs/levels-v2/를 제안했다.
통합 담당과 지도 담당의 기존 조율을 확인한 뒤 outputs/playable-battlefield-v1/로 즉시 정정했다.
outputs/battlefield-v2/ 및 outputs/encounters-v2/의 회귀 빌드와 충돌하지 않는다.

D06. 효과 계약과 비용
기존 포구는 리그 -X 전방을 muzzleFrame()으로 월드 방향으로 변환한다. 새 효과의 +Z 발사축/+Y 피격법선에 맞춘다.
실제 피해·접촉 이벤트만 명중을 만들고, 투사체 이동과 GLB 내장 이동을 이중 적용하지 않는다.
pause/retry/depart/clear/종료 및 풀 reset 규칙은 기존 전장 계약을 따른다.
신규 유료 작업은 사용자 Meshy 요청 범위에서 아트 담당 한 곳이 작업ID/비용/상태 장부를 관리한다. 총괄·전장 담당은 중복 제출하지 않는다.

D07. 첫 검토 조치와 증거 수준
기존 통합 source/검증 보고서 및 battlefield/VFX/레벨/항구 계약을 읽기 교차 검토한다.
소스 검사, 실제 입력 항해, 강제 보스 진입 회귀, 가속 논리 부하, 실제 브라우저 렌더를 구분한다.
현재 첫 지역 2회 회수·안전 철수는 확인되지만 전체6지역 보스 완주와 네 추가 무기 판정은 미완료다.
마지막 저장충돌 UI 수정의 표적 재검사와 최종 manifest 확인은 통합 담당에게 요청했다.

D08. 자율 실행 범위
첫 순환의 지시/검토/결과까지 진행한다. 자동 예약·상시 감시·추가 채팅·외부 배포·push는 만들지 않는다.
원래 채팅이 진행 중인 전체 기획서/무드보드 재전달을 중복 수행하지 않는다.
