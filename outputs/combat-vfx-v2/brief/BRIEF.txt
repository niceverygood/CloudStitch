Cloudstitch 전투 효과 v2 — 새 프로젝트 세션 작업 지시
작성: 2026-10-18. 사용자 최신 요청에 따른 실제 제작 작업이며 과거 자동화 재개가 아니다.

요청과 목표
현재 CloudStitch 프로젝트 폴더 안의 새 세션에서 작업한다. 사용자는 기존 전투효과 48종 + 무기별 공격 시연 6종, 총 애니메이션 GLB 54개가 비행선과 어울리지 않고 너무 AI로 만든 듯하다고 평가했다. Meshy를 실제 활용하여 감성적인 손그림, 입체감 있는 2D 인상의 3D 비행선과 어울리는 효과로 개선하고 비행선 위에서 시각화한다. 기존 결과를 숨기거나 덮어쓰지 않는다. 단순 색상 교체나 일반적인 구/원뿔 조각 반복으로 완료하지 않는다.

시작과 협업
AGENTS.md, README.md, docs/HANDOFF.md, docs/CONTINUE_PROMPT.md, 현재 git status와 실제 폴더를 먼저 읽는다. 문서 이후 다른 세션에서 항해 시제품 및 리그 작업이 진행 중이므로 문서의 미구현 설명을 그대로 최신 상태로 단정하지 않는다. 현 파일을 확인한다.
새 산출물은 outputs/combat-vfx-v2/, 재사용 코드는 tools/combat-vfx-v2/, 중간 파일은 work/combat-vfx-v2/에 둔다. 다른 세션의 airship-rig/battlefield/encounters/fleet/harbor/levels/save/shipyard 및 미추적 파일을 보존한다. package.json·공용 문서는 꼭 필요한 경우에만 충돌을 확인하며 수정한다. 기존 combat-vfx와 선체/무기 원본은 해시를 기록하고 보존한다. 저장소 상대 경로를 사용한다. API키·토큰·인증·원시 응답·계정 캐시를 산출물에 넣지 않는다. 이 요청에서 새 자동화, 추가 별도 채팅, 외부 메시지, 배포, 임의 git push를 하지 않는다.

제작 순서
전체 48효과와 6공격 시연을 같은 방향으로 개선하는 목표를 유지하되, 먼저 대표 6종으로 실제 방향을 만든다.
권장 첫 묶음: 작은 기관총 포구 섬광, 붓결 연기 퍼프, 함포 착탄/폭발, 화염 분사, 보호막 펄스, 수리 봉합.
작은 효과 하나를 완료하고 다음으로 이어간다. 첫 묶음에서는 공통 Meshy 기본 형상을 재사용할 수 있다. 48개를 각각 별도 유료 생성하거나 전체를 한 번에 제출하지 않는다. 비용·품질·시간에 맞춰 공통 형상 라이브러리와 효과별 연출을 구분한다. 동작하지 않는 계획/썸네일만 만들고 끝내지 말고 첫 실제 모델과 재생 가능한 선체 장면까지 작업한다. 첫 묶음 이후 무기 6종의 발사→비행→피격, 재질별 피격, 폭발/손상/지원 순서로 진행 기록을 남기며 이어간다.

Meshy 사용
설치된 meshy-3d-generation SKILL.md와 필요한 references를 읽고 그 CLI 경로를 따른다. 사용자 최신 요청은 Meshy를 이용한 새 생성/편집을 명시적으로 승인했다. 과거 인수인계의 '새 유료 생성 자동 시작 금지'를 이번 요청을 거절하는 이유로 쓰지 않는다.
생성 전 공식 가격/CLI dry-run과 실제 잔액으로 필요한 최초 묶음의 예상 크레딧을 확인하고 한국어로 알린다. 금액/잔액을 추측하지 않는다. 초기 필요한 제작은 진행하되 실패 뒤 추가 유료 재시도·리메시·리텍스처 등 별도 단계가 생기면 비용과 이유를 먼저 구체화한다. 한 요청은 안정적인 operation ID로 한 번 제출하고 동일 task를 이어서 기다린다. 생성 중 상태를 보존하고 확인한다. 이미지 기준이 필요하면 imagegen 스킬과 내장 이미지 도구로 선체와 맞는 독립 형상 기준을 먼저 만들 수 있다.
Meshy는 회화적인 메시/텍스처 기본 형상에 활용하고, 시간 연출은 별도로 의도해서 작성한다. 연기/불꽃에 사람용 자동 리깅을 적용하지 않는다. Meshy 생성 성공이 효과 애니메이션 완성이나 아트 품질 통과라는 뜻은 아니다. 다운로드한 실제 모델의 형상/텍스처를 렌더로 평가한다. 각 파일별 Meshy/로컬 제작·후처리 구분, task ID, 보고된 실제 크레딧, 해시·검증을 기록한다. 기존 v1 VFX의 신규 Meshy 작업은 0건이므로 Meshy로 만들었다고 잘못 설명하지 않는다.

시각화와 애니메이션
선택한 실제 비행선과 무기 GLB를 로드한 장면에서 v1/v2를 같은 크기/시간/카메라로 나란히 비교한다. 가능하면 현재 airship-rig-v1의 검증된 발사 위치를 조사하되 원본 및 다른 세션 코드를 덮어쓰지 않는다. 정확한 소켓이 없으면 근사 시연 위치라고 표시한다. 후보 게임 카메라(기울어진 정사영 또는 이에 가까운 시점), 크림 하늘/짙은 청록 배경, 실제 화면 크기에서 가독성을 확인한다. 단독 흰 배경 썸네일만으로 평가하지 않는다.
포구 섬광은 짧고 작게 읽히고, 연기는 방향과 소용돌이가 보이되 조준 대상/연결부를 덮지 않게 한다. 함포는 압력→불꽃→잔연기의 리듬, 화염은 점화→연속분사→접촉이 겹치는 흐름으로 구성한다. 보호막은 공격 폭발과 구별하고 수리는 천의 봉합/실 연결을 짧고 명확하게 보여준다.
가능한 메시 이동·회전·스케일 동작은 실제 GLB의 표준 TRS 애니메이션으로 저장한다. 부드러운 페이드/파티클/재질 애니메이션에 엔진 또는 브라우저 셰이더가 필요하면 별도 런타임 구현/레시피로 제공하고 GLB에 내장된 기능이라고 설명하지 않는다. 결과를 3D 파일이 아닌 단일 그림/스프라이트만으로 대체하지 않는다. 셀 셰이딩과 윤곽선 역시 뷰어 런타임과 내장 재질을 구별한다.
기존 outputs/combat-vfx/recipes.json과 sequence-catalog.json의 이벤트/축/종료 계약을 읽는다: +Y 위, 포구 +Z, 피격면 법선 +Y. 내장 투사체 이동과 실제 게임 물리를 이중 적용하지 않는다. 상태 반복은 상태 종료 시 중지하고 풀 반환 시 시간/변환/부착 참조를 리셋한다. 한 접촉에 고유 명중/재질 피격/일반 폭발을 모두 크게 겹치지 않는다. 작살의 도착 후 줄 유지와 화염의 중첩 타임라인을 보존한다. 시간과 상대 크기는 아트 가설이며 게임 피해/미터/사거리 확정값이 아니다.

산출물과 검증
첫 실제 개선 효과와 원본 대비 렌더, 실제 비행선에 붙여 재생하는 비교 뷰어, 효과별 GLB/소스/manifest/제작 기록을 만든다. 이후 대표 6종과 전체48+6의 상태를 구분한 catalog/progress를 작성한다. 미완료 효과를 완료로 세지 않는다. 기존54파일을 원본으로 보존한다.
실제 GLB 로딩·텍스처·시간에 따른 프레임 변화·루프/종료·재생/정지/스크럽/속도·선체/무기 원본 해시·오프라인 의존성·브라우저 오류·모바일 넘침·회전 잔상을 확인한다. OutlineEffect.autoClear = true를 명시적으로 유지한다. 형식 검증만 통과하고 아트가 어울린다고 단정하지 않는다. 비행선보다 효과가 지나치게 크거나 상세 표면을 가리는지, 작은 게임 화면에서 각 종류가 구분되는지 실제 렌더를 직접 확인한다.
새 세션 첫 진행은 한국어로 짧게 알리고 읽기에서 멈추지 말고 실제 제작을 시작한다. 첫 결과가 생기면 무엇을 만들고 실제 무엇을 검사했는지, 추가 크레딧/런타임/엔진/전체54개에 남은 한계를 명시해 보여준다.
