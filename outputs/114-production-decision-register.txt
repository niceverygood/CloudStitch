114. 제작 전 결정 목록과 승인 기준
54번 미확정 항목을 실제 다음 작업으로 이어가기 위한 인계 표. 사용자가 새 승인을 해야 현재 기획서를 읽을 수 있다는 뜻이 아니다. 다음 개발 단계의 팀 결정과 검증 기준이다.

이미 정한 기획 방향
구름 위 비행선 중심의 싱글플레이어 액션 RPG. 3D 사선 탑다운55도 기본 후보. 부품 단일 부모 트리, 연결부 분리·회수·장착의 순환. 기동·포격·인양3계열과21노드 스킬 초안. 주요4막과 최종 항해, 세 대안 결말. 기획 기준과 구현 완료는 구분한다.

D01 게임 엔진·파이프라인
결정 필요: 팀 경험, 목표 플랫폼, 모듈 충돌·저장·기낭 투명화 구현 방법.
검증 근거: 동일 회색상자 전장에서 이동·분리·인양·저장을 구현한 결과.
보류 이유: 현재 실제 엔진 프로젝트와 팀 정보가 없음. 특정 제품을 우월하다고 단정하지 않는다.

D02 목표 하드웨어·성능 예산
결정 필요: 해상도, 프레임 목표, 최대 동시 모듈·적·효과 수.
검증 근거: 큰 배·기낭 가림·연막·충격파가 겹친 대표 장면의 실제 프로파일.
보류 이유: 생성 PNG의 세부 묘사로 폴리곤·텍스처·메모리 예산을 추정 확정할 수 없음.

D03 소켓·선체 최대 크기
결정 필요: 모듈 단위 치수, 최대 폭, 통로 최소 폭, 포탑 가림 판정.
검증 근거:50번 기본선과47번 대표 빌드로33번 전장을 실제 통과.
보류 이유: U는 설계 거리 단위이며 모델 미터 변환이 아직 없음.

D04 성장 속도·스킬 재선택 부담
결정 필요: 출항별 레벨 속도, 프리셋 저장, 선택 노드 추천·재사용 흐름.
검증 근거: 연속 출항에서 메뉴 체류와 자발적 빌드 변경 관찰.
유지할 기준: 일반2개·궁극1개, 영구 설계도와 임시 출항 성장 구분.

D05 전투·경제 수치
결정 필요: 명중률, 파괴 시간, 제어 저항, 수리 부담, 연료 보급, 제작 가격.
검증 근거: 초행·경험자 모두의 실제 교전과 귀환 자원 분포.
유지할 기준: 산술 확인을 재미·공정성 검증으로 과장하지 않음. 양력·전력·연료 단위 구분.

D06 위험 도움과 난이도
결정 필요:19번7초/최소3초 유예 조정, 구조 시간 도움,111번 프리셋 배율.
검증 근거: 다양한 입력·접근성 조건에서 경고를 읽고 복구 행동까지 수행.
유지할 기준: 높은 난이도도 예고를 숨기지 않고 낮은 난이도도 이야기를 생략하지 않음.

D07 아군 피해·구조 위험
결정 필요: 직접 아군 피해 정책, 범위 화염과 호위선 충돌 처리.
검증 근거: 구조·호위 장면에서 의도치 않은 처벌과 오인 사격 관찰.
현재 권고: 일반 난이도 직접 아군 피해 없음 후보. 구조 설비의 명시된 위험은 별도. 확정된 시스템으로 표시하지 않음.

D08 저장·버전 이행
결정 필요: 안전 경계, 슬롯, 정산 거래 ID, 분리물 복원, 파일 충돌 복구.
검증 근거: 저장 중 종료, 자원 소비 직후 재개, 정산 반복 진입, 버전 업데이트.
유지할 기준: 저장 실패를 알리고 중복 보상을 막음. 물리 프레임 전체 동일 재현 약속 없음.

D09 보행 탐사와 콘텐츠 범위
결정 필요: 안전 정박 조사 공간, 동작 수, 실제 개인 임무·세력 임무 제작 수.
검증 근거: 한 선장실 조사와 한 동료 임무가 본래 함선 순환을 강화하는지 관찰.
유지할 기준: 보행 전투를 추가하지 않음. 모든 보드의 자산을 동시에 제작하는 약속 없음.

D10 인물·음성·현지화
결정 필요: 프리셋 리그, 호칭, 실제 녹음량, 번역 언어, 화면 글자 길이.
검증 근거:52번 기준 모델과75번 대사·51번 용어의 실제 화면/음성 적용.
유지할 기준: 선장25세, 오르 기계왼팔·자연오른손, 에다 성인 외형. 사용자 입력 이름은 안전한 표시 문자열.

D11 공개·배포 자료
결정 필요: 실제 게임 소개 범위, 스포일러 공개, 제목·상표·스토어 자료 검토.
검증 근거: 공개용60번 소개와 실제 구현 상태의 일치, 필요한 별도 조사.
유지할 기준: 생성 이미지나 회색상자 그림을 실제 게임 실행 화면으로 주장하지 않음. 이번 작업은 배포·판매·공개 업로드를 실행하지 않음.

개발 시작 권고
67번 기술 시제품의 P0~P4를 먼저 만든다. 이동·분리·회수·장착·복구·귀환을 검증한 뒤 짧은 기억과 마라를 추가한다. 새 엔진·플랫폼·일정은 팀 정보와 시제품 결과로 결정한다. 현재 인계물은 이 결정을 준비하는 기획 자료다.
