제작 범위
기존 비행선과 무기 여섯 종에 연결할 발사·비행·고유 명중, 재질별 피격, 폭발·환경, 상태 손상, 방어·지원 효과 48종의 실제 3D 원형을 제작했다. 여기에 기존 무기와 효과를 조합한 공격 시연 GLB6개를 별도로 만들었다. 이번 방식은 로컬 저폴리 메시와 glTF 표준 translation/rotation/scale 애니메이션이다. 신규 Meshy 유료 생성은0크레딧이며 새 이미지 생성·외부 효과 에셋 다운로드도 없다. 기존 무기6종의 과거 생성 비용과 이번 로컬 효과 제작을 구분한다.

production-spec.json은 제작 전에 작성한 원안이다. 실제 기본48개는 catalog.json과 assets/, 개별 구조·애니메이션·파일 검사는 manifests/를 기준으로 삼는다. 합성6개는 sequence-catalog.json과 sequences/에 있다. 최종 브라우저/포맷 검사 통과 값과 합계는 최신 정식 검사 기록을 따른다. 기획에 정의됐다는 사실만으로 검사·엔진 연동이 완료됐다고 해석하지 않는다.

바로 보기와 파일
gallery.html: 48개 기본 효과를 범주·무기로 고르는 갤러리. PNG는 실제 GLB의 대표 시간 렌더이며 전체 시간 동작은 작업대에서 본다.

catalog.json / sequence-catalog.json: 실제 모델 경로·표시 길이·원형 상태·구성 효과 타임라인. 내부 model/preview 경로는 각 카탈로그 기준 상대 경로다.
assets/ / sequences/: 실제 기본 효과 GLB와 별도 합성 시연 GLB.
manifests/: 개별 기본 효과의 파일·해시·표준 transform 채널·실제 움직임 검사 기록.
previews/ / sequence-previews/: 실제 애니메이션의 시간 한 지점을 고정한 대표 PNG.
recipes.json: 48효과의 의미상 trigger·시간·좌표·종료 조건과6개 시연의 실제 start/end 타임라인, 공용 피격 선택·엔진 통합 계약.
progress.json: 전체 파일 제작 진행. 최종 검증 정보가 갱신됐다면 그 최신 기록과 개별 manifest를 함께 읽는다.

HTML은 실제 GLB와 코드를 포함한 오프라인 미리보기다. 재생/일시정지·처음부터·반복·속도·시간 스크럽, 드래그 회전·휠 확대·오른쪽 드래그 이동, 처음 시점·화면 맞춤·자동 회전, 윤곽선 선택을 제공한다. 목재·금속·천 비교 표적과 크림/짙은 청록 배경을 바꿀 수 있다. 비교 표적은 충돌체나 실제 적이 아니다. GLB 다운로드는 실제 모델/클립 데이터다. 현재 효과 작업대는 기존 무기 작업대의 손그림/셀/원본3모드 전환과 별개로, 원본 vertex color/unlit 표면과 선택 윤곽선을 보여준다.

production-spec.json의 effects 배열에는 중복 없는 영어 kebab ID, order1~48, 한·영 이름, category, 해당 weapon_id 또는 null, 목적, duration_seconds, loop, 연결 이벤트 설명, 도형·색, 장착 좌표, 내장 변환 동작과 통합 한계를 기록한다. 48종은 기본 효과 세트이며 모든 스킬·보스·지역·게임 연출을 만든 범위는 아니다.

아트 방향
선택 비행선·무기의 크림 천, 청록 기계, 꿀빛 목재, 황동, 산호 수선 포인트를 유지한다. 넓은 도형, 단순한 명암, 읽기 쉬운 윤곽으로 그림 같은 인상을 낸다. 효과도 실제 입체 구·원뿔·다면체 쐐기·고리·두께 있는 조각으로 구성한다. 스프라이트 시트나 PNG 카드 장면을 실제 메시 애니메이션으로 설명하지 않는다. 다른 작품의 고유 효과·로고·장면을 복제하지 않는다.

기관총 섬광은 함포 단발보다 작고 짧게 한다. 박격포는 상향 궤적, 작살은 촉과 줄, 사슬탄은 연결된 두 탄구, 화염은 짧은 원뿔로 구별한다. 방어·수리·견인은 공격 폭발과 다른 고리·실·연결 형태를 사용한다. 색만으로 상태를 읽게 하지 않고 도형·방향·동작도 달리한다. 연결부와 목표를 가리는 연기·화염·파편의 겹침은 최종 엔진 장면에서 다시 조정해야 한다.

실제 3D 애니메이션의 범위
기본48개는 정점 채색(vertex colors)과 KHR_materials_unlit 재질을 사용한 실제 메시이며 이미지 텍스처 없이 색을 가진다. 표준 glTF transform 클립이 메시 조각의 위치·회전·크기를 시간 키로 바꾼다. 입체 조각이 움직이는 데이터이며 캐릭터용 본 리깅은 필요하지 않다. 합성6개는 기존 무기 GLB를 포함하므로 그 무기의 텍스처가 함께 들어갈 수 있다. 재질/불투명도/셰이더 속성의 애니메이션, 파티클 방출기, 실제 연체 물리, 실시간 바람, 깊이 페이드, 블룸, 왜곡, 오디오·진동·카메라 흔들림은 포함하지 않는다.

불꽃·증기·연기는 불투명한 입체 도형일 수 있다. 크기를 줄여 표시를 끝내는 동작은 반투명 페이드와 다르다. 불투명 덩이의 가림, 너무 강한 윤곽선, 끝 프레임에서 반복 시작으로 돌아가는 느낌은 실제 화면에서 검토한다. 정점색과 unlit 재질은 GLB에 포함되지만 선택 윤곽선은 작업대 런타임 효과다. 엔진에서의 unlit 확장 지원·투명도·셀 셰이더·윤곽선을 따로 확인해야 한다.

시간·크기·반복
duration_seconds의0.2~3초는 아트 클립 한 번 또는 반복 한 주기의 길이이며 실제 탄속·장전·피해·상태 지속시간이 아니다. loop=true는 작업대와 후속 엔진에서 반복을 요청하는 메타데이터다. glTF 표준 애니메이션 파일 자체가 무한 반복 정책을 강제하지 않는다. 엔진은 실제 상태가 끝나면 반복 표시를 중지하고, 일회성 클립이 끝나면 인스턴스를 제거하거나 풀로 반환해야 한다.

E는 전시·비교용 상대 효과 단위다. 실제 미터, 기존 기획의 U, 피해 반경, 소켓 크기, 최종 화면 픽셀·성능 예산은 아직 미정이다. 포탄·작살·사슬탄의 내장 로컬 이동은 전시용이며 실제 엔진의 발사체 이동과 중복 적용하지 않도록 조정해야 한다. 화염 클립의 반복 주기를 실제 최대 연속분사·냉각 시간으로 해석하지 않는다.

공격 시연의 타임라인
합성6개의 실제 component_effects.start/end는 sequence-catalog.json과 recipes.json에 기록했다. 기본 효과의 단독 클립과 달리 합성할 때 시간·위치를 조정한다. 박격포 합성 시연은3.5초이며 기본48개 클립의0.2~3초 규칙이나 실제 장전시간과 다른 범위다. 화염은 점화 뒤 분사와 접촉이 겹치며 독립 탄환 세 발을 쏘는 구조가 아니다. 작살 시연은 현재 카탈로그에서0.2~1.3초 비행 뒤 visible_until2.7초까지 작살/줄을 유지한다. 이것은 도착 뒤 연결을 보여주는 연출이며 실제 케이블 장력·물리 견인·소유권 변경을 구현하지 않는다.

합성 공격 시연은 기존 무기 원본을 보존한 별도 파일이다. 단일 메시 무기의 포신을 분리하거나 정확한 발사 소켓·yaw/pitch·장전·반동 리그를 완성한 파일이 아니다. 포구는 시연을 위한 근사 위치다. 고정 타임라인의 명중 시각이 실제 충돌을 판정하거나 무기 발사 속도·피해량을 결정하지 않는다.

좌표와 연결
일반 자산 좌표는 +Y 위, +Z 전방이다. 포구 효과의 원점은 실제 포구 중앙이며 +Z를 발사 방향으로 맞춘다. 피격면 효과는 원점이 접촉점, +Y가 표면 바깥 법선, +Z가 진행 방향의 표면 접선이다. 견인 연결 효과는 +Z를 시작점에서 끝점으로 향하게 하고 실제 길이와 끝점 갱신은 엔진에서 처리한다.

trigger는 후속 통합 시 연결할 의미상의 이벤트 설명이다. 특정 엔진의 확정 API나 실행된 전투 코드가 아니다. 현재 무기 GLB는 단일 메시이므로 실제 포구·회전축·발사 소켓이 별도로 완성되어 있지 않다. 호스트 부품·표면·포구·두 연결 끝점은 후속 편집과 게임 판정에서 제공해야 한다. 외부 갑판 배치나 효과 위치 비교는 소켓·충돌·구조 부모·실제 장착 완료가 아니다.

실제 충돌 위치와 표면 법선은 엔진이 결정하고 효과는 그 결과에 붙인다. 피격면 +Y를 표면 법선에, 포구 +Z를 실제 발사 방향에 맞춘다. 내장 이동을 그대로 재생하면서 엔진 발사체를 다시 움직여 이중 이동시키지 않는다. 상태가 끝나면 loop stop 한다. 풀로 반환할 때 재생 중지, animation time=0, action/mixer·loop 상태, 표시용 root 위치·회전·크기, 부착 부모·대상·두 끝점 참조를 기본값으로 되돌리고 다음 재생 때 새 좌표를 부여해야 한다. 이 풀 반환 정책은 통합 계약이며 현재 실제 게임의 풀링 구현은 아니다.

전투 규칙과 시각 효과를 구별
기준은 outputs/21-weapons-combat-roles.txt, outputs/72-weapon-mount-readability.txt, outputs/112-system-rules-reference.txt다. 실제 사격은 거리·포각·장전·가림을 만족해야 하며 자기 선체를 통과하지 않는다. 기본 탄환 매발 구매·새 연료 차감·새 피해/회복 배율·무적·새 상태효과를 이 효과 명세가 추가하지 않는다.

피격·도탄·약점·관통·막음은 전투 판정의 결과가 먼저 있어야 한다. 관통 출구 모델이 있다고 함포 일반탄에 관통을 추가하지 않는다. 사슬탄의 얽힘 표시가 상태 강도와 중첩 규칙을 정하지 않는다. 화염의 그을림 표시가 점화 지속 피해를 자동 적용하지 않는다. 엔진 정지·기낭 파열 표시가 출력0이나 침하를 결정하지 않는다. 장식 파편은 인양 가능한 스크랩 드롭이 아니다.

부품 분리는 부모 연결 절단과 하위 묶음 분리가 실제로 판정된 뒤 표시한다. 회수·소유권 변경·화물·제작·소켓 장착은 서로 다른 상태다. 견인 흐름·장착 잠금 효과가 그 처리를 대신하지 않는다. 수리·회복 표시는 실제 견적·자원 차감·대상·복구 수치를 판단하지 않는다. 공용 재질 피격과 무기 고유 명중을 동시에 쓸지는 겹침과 가독성을 보고 엔진 통합 단계에서 정한다.

기본 선택은 무기 고유 명중 하나 또는 실제 재질 공용 피격 하나를 주 효과로 쓰는 것이다. 고유 명중+재질 피격+일반 폭발을 모두 같은 위치에 기본 재생하지 않는다. 보조 재질 조각을 추가할 때는 크기·빈도와 연결부 가림을 확인한다. 약점·도탄·관통 출구·빗나감은 실제 결과에 맞춰 선택하고, 작업대 비교 표적이 그 선택 판정을 대신하지 않는다.

검증과 완료 기록
- ID48개, order1~48, 분류18/8/8/8/6, duration_seconds0.2~3초, weapon_id 매핑과 중복·누락을 검사한다.
- 실제 GLB의 메시·삼각형·재질·텍스처 유무·표준 transform 채널·클립 길이·파일 크기·SHA256을 기록한다.
- 전면·측면·후면·기본 게임 후보 시점에서 실제3D 형상과 시간 동작을 확인한다.
- 작업대의 표시 모드·재생·멈춤·다시보기·반복·모바일 화면·외부 요청·오류·잔상을 실제로 검사한다.
- 기획의 planned와 실제 모델/클립/QA 완료 상태를 구별한다. 완료 상태와 실제 파일 경로는 catalog/manifest를 따른다.
- 파일 검사와 브라우저 렌더를 실제 엔진 임포트·전투 재미·정확한 충돌·밸런스·대규모 성능 검증으로 표현하지 않는다.

소스와 로컬 재현
tools/combat-vfx/README.md를 먼저 읽는다. 저장소 루트의 Node.js20 이상·package-lock.json으로 npm ci를 수행하고, 브라우저 캡처/검사가 필요하면 기존 setup:browser 절차로 Playwright Chromium을 준비한다. 이 안내 때문에 새 API 키나 Meshy 작업이 필요하지 않다.

tools/combat-vfx/core.mjs: 저폴리 메시·정점색·표준 변환 애니메이션의 공통 제작 코드.
tools/combat-vfx/primary.mjs / secondary.mjs: 무기별·공용 효과의 실제 도형과 시간 동작.
tools/combat-vfx/generate.mjs: 기본48개 또는 지정한 EFFECT_ID의 GLB와 구조/애니메이션 검사 기록을 로컬 제작한다.
tools/combat-vfx/sequences.mjs: 기존 무기와 효과를 조합한 별도6개 공격 시연을 만든다.
tools/combat-vfx/build.cjs / viewer.js / template.html: 실제 GLB를 포함하는 오프라인 작업대 빌드와 재생 UI.
tools/combat-vfx/capture.cjs: 실제 클립 시간을 고정해 대표 프레임을 캡처한다.
tools/combat-vfx/gallery.cjs / overview.cjs: 실제 캡처를 모아 갤러리·대표 보드를 만든다.

로컬 재현 명령 예시(저장소 루트):
node tools/combat-vfx/generate.mjs
node tools/combat-vfx/sequences.mjs
node tools/combat-vfx/build.cjs
node tools/combat-vfx/build.cjs outputs/combat-vfx/sequence-catalog.json outputs/combat-vfx/attack-sequences.html
node tools/combat-vfx/capture.cjs

이 명령들은 로컬 산출물을 다시 쓰므로 작업 전 현재 파일 변경과 원본을 보존한다. 생성·빌드·캡처 성공이 곧 최종 브라우저/포맷 검사 통과는 아니다. 캡처 선택·경로·시간 인수와 검증 도구 사용은 tools/combat-vfx/README.md와 최신 정식 검사 기록을 따른다.

보존과 이후 작업
기존 비행선·무기·원화·기획은 보존한다. 실제 엔진 파티클/셰이더/오디오·물리·전투·풀링·소켓·성능 프로파일은 후속 작업이다. API 키·토큰·인증을 문서나 로그에 넣지 않는다. PNG·GLB 등 큰 파일은 기존 Git LFS 규칙을 확인한다. ZIP·work·node_modules는 기본적으로 커밋하지 않으며 원격 push는 사용자 요청 범위에 따른다.
