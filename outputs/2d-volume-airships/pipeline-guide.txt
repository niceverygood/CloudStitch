입체감 있는 2D 비행선 — 어떤 방식으로 만들면 좋을까?
작성일: 2026-10-18

지금의 비행선 게임에는 “부품은 3D로 만들고, 화면은 그림처럼 보이게 표현하는 방식”을 먼저 권합니다. 선체·기낭·프로펠러·포탑을 조립하고 방향을 자유롭게 바꾸는 게임이라면, 같은 모델을 여러 각도에서 보여 주고 장비를 교체할 수 있기 때문입니다.

다만 카메라가 고정되고 방향 변화도 적은 작은 시제품이라면, 부품별 2D 이미지를 겹쳐 놓고 움직이는 방식으로 더 빨리 출발할 수 있습니다. 어느 쪽이 저렴한지는 회전 범위와 모듈 교체 규칙에 달려 있습니다.

그림의 생김새와 실제 제작 방식은 별개입니다. 평평한 색, 윤곽선, 입체적인 명암은 여러 방식으로 만들 수 있습니다. 참고 스크린샷만으로 WANDERBURG가 쓰는 엔진이나 렌더링 방식을 확정하지 않습니다.

1. 비교할 수 있는 네 가지 제작 방식

① 실시간 3D + 만화풍 표현
3D 모델을 게임 안에서 직접 보여 줍니다. 정사영 또는 약한 원근의 카메라, 단순한 색과 명암, 필요할 때 윤곽선을 조합해 2D 같은 인상을 만듭니다.
장점: 방향을 자유롭게 돌리고, 장비를 붙이거나 바꾸기 편합니다. Meshy 모델도 이 경로에서 활용할 수 있습니다.
작업: 모델의 밀도와 부품 구조를 정리하고, 재질·조명·카메라를 맞춰야 합니다. 3D 생성 결과만으로 원하는 그림체가 완성되지는 않습니다.
맞는 경우: 여러 방향 회전과 모듈 조립이 중요한 현재의 비행선 액션 RPG.

② 손그림 프레임 애니메이션
방향과 동작에 맞는 그림을 여러 장 만들고 순서대로 재생합니다.
장점: 실루엣, 표정, 과장된 동작, 붓질을 세밀하게 통제할 수 있습니다.
작업: 방향·동작·장비가 늘수록 새 그림과 수정 작업이 늘어납니다.
맞는 경우: 방향 수가 적고 손그림 자체의 표현이 게임의 핵심일 때.

③ 3D 제작 → 2D 스프라이트로 렌더
제작은 3D로 하고, 정해진 방향과 동작을 투명 배경 이미지로 내보냅니다. 게임에서는 이 이미지를 2D 스프라이트로 사용합니다.
장점: 같은 모델에서 일관된 입체감과 여러 방향 이미지를 얻습니다. 게임의 표시 방식은 2D로 구성할 수 있습니다.
작업: 방향별 출력, 프레임 정렬, 피벗, 그림자, 이미지 묶음 관리가 필요합니다. 부품이 겹치는 순서와 장착부 연결도 확인해야 합니다.
맞는 경우: 게임을 실제 2D로 구성하고 싶고, 카메라와 방향 수를 미리 정할 수 있을 때.

④ 2D 부품 레이어 이동·회전
기낭, 선체, 엔진, 포탑 등을 따로 그려 겹친 뒤 움직입니다. 단단한 부품은 회전과 이동으로, 휘어지는 부분은 필요할 때 2D 뼈대로 표현합니다.
장점: 적은 이미지로 조립과 간단한 움직임을 빠르게 검증합니다.
작업: 이미지를 돌려도 보이지 않던 옆면·뒷면은 생기지 않습니다. 시점 변화가 커지면 다른 방향의 그림이 필요합니다.
맞는 경우: 고정된 시점에서 가장 작은 프로토타입을 만들 때.

위 비교는 기능과 제작 과정을 바탕으로 한 권장 판단입니다. 특정 방식의 제작비가 항상 더 낮다는 뜻은 아닙니다.

2. 비행선 전체에 캐릭터용 뼈대를 넣어야 할까?

처음부터 그럴 필요는 없습니다. 선체가 떠오르거나 흔들리는 움직임, 프로펠러의 회전, 포탑의 조준, 크레인의 회전은 부품 오브젝트의 위치와 회전으로 만들 수 있습니다. Unity의 Animation 창도 이런 GameObject 속성을 키프레임으로 기록합니다.
https://docs.unity3d.com/6000.0/Documentation/Manual/animeditor-AnimatingAGameObject.html

사람의 팔·다리, 생물의 날개·촉수, 휘어지는 천처럼 실제 형태가 변해야 하는 부분에는 뼈대와 스키닝을 고려합니다. 2D에서도 Unity Sprite Skin이 뼈대에 따라 이미지 메시를 변형하는 방식을 지원합니다.
https://docs.unity3d.com/Packages/com.unity.2d.animation@13.0/manual/SpriteSkin.html

Meshy 자동 리깅의 범위는 API와 웹 도구를 구분해야 합니다. 현재 Rigging API 문서는 표준 인간형 중심이며 비인간형 자산에 적합하지 않다고 안내합니다. 웹 도움말에는 Humanoid, Quadruped, Smart Rig Beta가 있습니다. 같은 도움말 기준으로 Quadruped의 기본 동작은 걷기뿐이고, Smart Rig 모델은 Meshy 애니메이션 라이브러리를 아직 사용할 수 없습니다. 이 기능이 기계식 비행선의 회전축과 조준 동작을 자동 완성해 준다고 기대하지 않는 편이 좋습니다.
https://docs.meshy.ai/en/api/rigging
https://help.meshy.ai/en/articles/16231707-how-to-create-3d-animation-with-auto-rigging

3. Meshy를 효율적으로 쓰는 범위

전체 조립 규칙을 먼저 정한 뒤 선체·기낭·엔진·포탑 같은 교체 가능한 부품의 형태 탐색에 활용하는 접근을 권합니다. 최신 Image-to-3D의 Smart Topology는 부품 분리를 안내하지만, 결과가 원하는 교체 단위와 맞는지는 직접 확인해야 합니다. 잘못 붙은 부분은 분리하거나 부품을 따로 제작하고, 회전축·피벗·장착 위치를 맞춥니다.
https://docs.meshy.ai/en/webapp/image-to-3d

Remesh는 폴리곤 수와 토폴로지를 조정합니다. 장착 규격이나 피벗 설계를 대신하는 작업은 아닙니다. 모델의 실제 구조와 화면에서 보이는 품질을 확인한 뒤 최적화 수준을 정하세요.
https://docs.meshy.ai/en/webapp/guides/3d-model/remesh

GLB에는 텍스처를 포함할 수 있습니다. FBX는 별도 텍스처 파일을 동반하며, Meshy는 Unity용으로 FBX를 권장합니다. 내보낸 뒤에도 엔진에서 재질과 크기를 확인해야 합니다. 프린팅용 Auto Split은 입력 텍스처를 보존하지 않으므로, 게임 부품 분할의 기본 경로로 선택하지 않습니다.
https://help.meshy.ai/en/articles/15724161-how-to-export-meshy-models-with-colors-and-textures
https://docs.meshy.ai/en/api/auto-split

기존 9개 Meshy GLB의 model-manifest.json 검사 기록에는 각 파일이 단일 메시이며 745,968~1,394,654개 삼각형으로 기록되어 있습니다. 약 75만~139만 삼각형의 고밀도 원본입니다. 지금 바로 게임에 넣을 수 있는 완성 자산으로 보지 말고, 부품 분리·메시 단순화·재질·장착 위치·충돌·LOD 등을 실제 사용 조건에 맞춰 정리해야 합니다. 단일 메시라는 기록만으로 모든 면이 물리적으로 하나로 붙었다고 단정하지는 않습니다.

4. 정말 2D로 만들고 싶다면

3D 모델과 부품 애니메이션을 먼저 만든 다음, 고정 카메라에서 필요한 방향만 투명 배경으로 출력하는 방식을 선택할 수 있습니다. Blender는 정사영 카메라와 투명 배경 렌더를 지원합니다.
https://docs.blender.org/manual/en/4.2/editors/3dview/navigate/projections.html
https://docs.blender.org/manual/en/latest/render/cycles/render_settings/film.html

작업량의 예로 “8방향 × 4동작 × 동작당 6프레임 = 192장”을 생각할 수 있습니다. 이것은 설명용 가정이며, 참고 게임이나 현재 게임의 확정 사양이 아닙니다. 엔진과 연출에 따라 필요한 수는 달라집니다.

모듈 게임에서는 가능한 모든 장비 조합을 완성 비행선 이미지로 굽는 방식부터 시작하지 마세요. 선체·엔진·포탑 등을 부품별로 출력하고 게임에서 조립하면 재사용할 수 있습니다. 대신 모든 부품의 방향, 크기, 피벗, 장착 기준점, 겹침 순서, 그림자 규칙을 맞춰야 합니다. 복잡하게 교차하거나 가려지는 장비는 별도 보정이 필요할 수 있습니다.

5. 가장 작은 다음 제작 단계

선체 1개 + 엔진 1개 + 포탑 1개를 단순 도형으로 조립합니다. 먼저 이동·회전·조준·장비 교체가 재미있게 작동하는지 확인합니다. 그다음 카메라와 화면상 크기를 정하고, 한 후보의 형태와 색을 입힙니다.

자유 회전이 필요하면 3D 부품 + 만화풍 표현을 이어 갑니다. 시점이 고정되고 방향도 적다면 2D 부품 레이어로 빠르게 시험합니다. 실제 게임 화면을 2D로 확정한 경우에는 3D에서 필요한 방향만 렌더하는 경로를 검토합니다.

6. 이번 갤러리의 범위

이번 결과는 “입체감 있는 2D 정지 콘셉트 9종”입니다. 완성 애니메이션이나 스프라이트 시트가 아닙니다. A·B·C의 세 분위기와 각 세 형태를 비교하고, 다음에 제작할 비행선의 실루엣과 색을 고르는 시안입니다. 갤러리의 원안 형태 설명은 designs.json의 설계 설명을 옮긴 것으로, 실제 생성 이미지가 그 설명을 모두 만족한다는 보증은 아닙니다.

제작 자산으로 쓰려면 선택한 시안에서 부품별 컷아웃, 필요한 방향별 모습, 일관된 크기와 피벗, 장착 기준점, 애니메이션 프레임 또는 뼈대, 충돌 영역 등을 추가로 만들어야 합니다. 9종 PNG와 별도 게임 화면 스타일 참고 이미지의 저장을 완료했습니다. 9종은 모두 1536×1024 RGBA이며 투명 영역을 확인했습니다. 별도 장면은 1672×941 RGB 이미지입니다. 모든 결과는 정지 이미지이며, 실제 게임 자산 제작과 엔진 검증은 후속 단계입니다.
